# 체험 데이터 삭제 계획 (기한: 2026-11-01)

처리방침 약속: "체험이 끝나는 날부터 일주일 안에 탈퇴하지 않은 이용자의 정보도 삭제한다." 체험은 10/25 23:59에 끝났으므로 **11/1 23:59까지** 지운다. 발표(11/2~)보다 하루 앞이라 발표용 숫자와 화면은 삭제 전에 확정한다.

## 삭제 전 확정한 숫자 (운영 관리자 화면, 2026-10-29 15:10 조회, 가입일 10/22~10/25)
관리자 화면의 "기간별 이탈 분석"(실제 기록 기준)에서 읽은 값이에요. 캡처는 `관리자화면_캡처/`에 있어요.

| 단계 | 인원 | 앞 단계에서 빠짐 |
|---|---|---|
| 가입 | 27 | — (중복 가입 1명 포함, 중복을 빼면 26) |
| 대상 확인 | 26 | 1 |
| 건강정보 입력 | 23 | 3 |
| 설문 제출 | 22 | 1 |
| 분석 결과 | 22 | 0 |
| 챌린지 시작 | 19 | 4 (1명은 앞 단계 없이 시작) |
| 다음 4주 시작 | 4 | 15 |

챌린지를 시작한 19명의 첫 4주 직접 기록일(자동 채움 제외, 하루로 셈):

| 직접 기록일 | 인원 | 4주를 마침 | 다음 4주 시작 |
|---|---|---|---|
| 0일 | 4 | 0 | 0 |
| 1일 | 3 | 0 | 0 |
| 2일 | 4 | 0 | 0 |
| 3일 이상 | 8 | 7 | 4 |

- **3일 이상 8명, 4주 결과 7명, 다음 4주 시작 4명**은 멘토링 때 브리핑한 값과 같아요. **첫 3일을 못 넘긴 사람은 4+3+4=11명(19명 중)** 이라 이 값도 맞아요. 확정이에요.
- 남은 확인: 가입 27명에는 이메일 오타 중복 1명이 들어 있어서, 발표에서는 "실제 가입 26명"으로 쓰고 관리자 화면 숫자(27)와의 차이를 한 줄로 설명하세요.
- 같은 화면의 위쪽 "진행 현황"(가입 32명 등)은 팀원 계정과 체험 기간 밖 가입이 섞이고 건너뛴 단계도 세서 발표에 쓰면 안 돼요.

## 무엇을 지우나 (효민 확인 반영, 2026-10-29)
- **지운다**: 체험 버전을 쓴 사람 전부. 가입일 10/22 이후이므로 **체험 종료 후 가입한 10/26 가입자 1명도 대상**이고, 이메일 오타 중복 가입 1명(첫 계정은 가입 단계에서 멈춤)도 들어간다. 미리보기는 **28명 안팎**으로 나온다. 그들의 건강정보·설문·챌린지·커뮤니티 글·파이·문의·푸시 구독은 계정 삭제 기능(`delete_account_data`)이 `user_id`가 있는 표를 한꺼번에 지운다.
- **남긴다(확정)**: 팀원 계정 4명. 서버 `.env`의 `ADMIN_EMAILS`에 든 관리자 계정이라 스크립트가 자동으로 빼고, 처리방침이 말하는 "체험 이용자"도 아니다. 시연 영상용 계정(`@paeon-demo.kr`)은 로컬 DB에만 있어 운영에는 없다.
- **지워도 남는 것(의도)**: 접속 기록(`access_logs`, 3개월 보관)과 관리자 행위 기록(`admin_audit_logs`)은 `user_id`가 없어 남는다. 법정 보관 항목이라 처리방침에 적혀 있다.
- **지우지 않는 집계**: 숫자(인원 수, 비율)만 문서에 남긴다. 개인을 알아볼 수 있는 값은 남기지 않는다.

## 삭제 방법과 주의
이메일 패턴 방식(`purge_test_accounts`, 관리자 화면 "테스트 계정 삭제" 탭)이 아니라 **가입 시각으로 고르는 `purge_trial_accounts`(#217)** 를 쓴다. 이메일이 암호화돼 있어 패턴 방식은 흔한 도메인에서 범위를 잡기 어려웠고, 새 스크립트는 이를 피한다.

```
# 1) 미리보기 (기본). 이메일은 안 나오고 회원 번호 끝 8자리·가입 시각·도메인만 나온다
python -m app.scripts.purge_trial_accounts --since 2026-10-22
# 2) 실제 삭제. 미리보기에서 본 인원을 --confirm에 넣어야 지워진다(다르면 아무것도 안 지움)
python -m app.scripts.purge_trial_accounts --since 2026-10-22 --apply --confirm <인원>
```
- 관리자(`ADMIN_EMAILS`)는 늘 자동 제외. 남길 도메인이 있으면 `--keep-domain example.com`.
- 스크립트 이름은 `purge_trial_accounts`(밑줄 두 개)다. #217이 `main`에 머지돼야 서버에서 쓸 수 있다.
- **미리보기 인원이 28명 안팎이 아니면 멈추고 목록(가입일별·도메인별)을 팀에 공유한다.**
- 실패가 있으면 서버가 출력하니, `실패 0명`이 나올 때까지 다시 돌린다.

## 백업 (효민 계획)
- 서버 DB 백업은 7일 뒤 자동으로 사라진다. 삭제 후 7일이 지나면 개인정보가 든 백업이 남지 않는다.
- 맥북 사본과 10/17 스냅샷은 효민님이 삭제 날 직접 정리한다.
- 삭제 뒤 새 백업과 복원 시험을 한 번 한다.
