## 2. 핵심 발견 (문제 → 근거 → 조치)

| 발견 | 설문 근거 (10명 중) | 조치 |
|---|---|---|
| "양호"를 "건강에 문제없음"으로 오해함 | 오해 6명, 바르게 이해("입력한 정보 기준 위험이 낮음") 3명, 결과 못 봄 1명 (5번 문항) | "양호" 옆 문구와 면책 안내 수정 |

주관식에서 나온 사용성 문제 (9·17번):

- 혈압 수축기·이완기 입력란이 헷갈림
- 첫날 입력과 4주 후 입력이 구분되지 않음
- 입력 오류 안내가 잘 안 보여 버그로 오해함
- 중요한 버튼 색이 너무 연함 (전부 파스텔톤)
- "건강 앱보다 커뮤니티 느낌", "사람·챌린지가 많아지지 않으면 심심함" (40대 1명)

## 3. 만족 지표

- 계속 쓰고 싶음 (10번): 매우 그렇다 2명, 그렇다 5명, 보통 3명 → 긍정 7명
- 지인 추천 의향 0~10점 (8번): 9~10점 3명, 7~8점 5명, 0~6점 2명. NPS +10 (10명이라 참고용)
- 4주 결과를 본 5명 전원 "다음 4주도 해 보고 싶어졌다" (3·3-1번)
- 계속 사용한다면 이유 (13번, 복수 응답): 장기 생활습관 기록 6명, 현재 건강 정보 확인 4명, 미션 달성·보상 3명, 전후 변화 확인 3명, 커뮤니티 1명
- 화면 속도 (7번): 불편 0명 (전혀 없음 8명, 한두 번 있었지만 괜찮음 2명)
- 막힌 곳 (6번, 복수 응답): 없었음 6명, 커뮤니티·파티 2명, 생활습관 설문·4주 재입력·대상 확인·건강정보 입력·미션 기록 각 1명

## 4. 3일 기록 미완료자

- 설문 응답자 중 3일 기록을 못 채움 3명 (3번)
- 설문은 익명이라 응답과 계정을 연결할 수 없음. 인터뷰 대상을 찾는 방법은 아래 둘 중 팀에서 선택

| 방법 | 절차 | 장점 | 주의 |
|---|---|---|---|
| A. 공개 요청 | 체험자를 모은 채널(팀원별 지인 단톡방·DM)로 27명 전원에게 같은 메시지를 보내고, 본인이 답장하면 인터뷰 | 개인정보 조회 없음. 바로 가능 | 응답자가 적을 수 있음 |
| B. DB에서 미완료자 계정 확인 | ① `체험_집계.sql`의 `testers`·`first_cycle`·`autofilled` 기준으로 "챌린지를 시작했지만 자동 채움 기록이 없는 사람"(3일 미만 그룹)의 user_id 목록을 뽑음 ② 관리자 화면 가입자 상세의 이메일 보기(`GET /admin/users/{user_id}/email`)로 이메일 확인 ③ 해당 지인에게 연락 | 대상을 정확히 앎 | 관리자 화면의 단계(stage)는 "챌린지 시작"까지만 보여 줘서 3일 미만인지 알 수 없음 → ①의 SQL 필요. 이메일을 볼 때마다 관리자 기록(`user_email_view`)에 남음. 가입 때 받은 연락처를 인터뷰 섭외에 쓰는 것이 개인정보 처리방침의 이용 목적에 들어가는지 먼저 확인 필요 |

- 미완료 인원수는 방법과 상관없이 `체험_집계.sql` 결과의 3일 미만 그룹으로 집계함 (숫자만 사용)

## 6. 문항 응답 주의

- 2번(어디까지 해 보셨나요): 3명이 지나온 단계를 모두 고르지 않고 마지막 단계("4주 전후 비교")만 고름. 가장 멀리 간 단계로만 읽으면 4주 비교까지 5명, 미션 기록까지 4명, 챌린지 시작까지 1명
- 가장 멀리 간 단계로 읽어도 2번과 3번이 맞지 않는 응답 1건: 2번에서 "4주 전후 비교"까지 갔다고 했는데 3번(4주 체험 결과를 봤나)은 "잘 모르겠다". 4주 전후 비교는 4주 체험 결과 다음 단계라 결과를 봤어야 함. 화면 이름("4주 체험 결과")을 알아보지 못한 것으로 추정
- 4주 체험 결과를 봤다면서 2번에서 "4주 전후 비교"를 고르지 않은 1건은 모순 아님. 결과를 본 뒤 4주 재입력을 하지 않았으면 그대로임
- 3번 "잘 모르겠다"인데 3-1번(결과 화면을 보고 든 생각)에 "다음 4주도 해 보고 싶어졌다"고 답한 1건도 있음
- 그래서 4주 결과를 봤는지는 3번 문항에서 "네"라고 답한 5명으로만 셈
