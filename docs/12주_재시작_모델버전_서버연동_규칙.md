# 12주 재시작 · 모델 버전 표시 — 프론트가 기대하는 서버 규칙

프론트(이슬)를 먼저 만들었고, 아래 규칙대로 서버가 응답하면 바로 연결됩니다.
**서버에 아래 항목이 없으면 화면은 지금과 똑같이 동작합니다**(새 버튼·안내만 안 보임). 그래서 서버가 먼저 나가도, 프론트가 먼저 나가도 깨지지 않습니다.
배경: PR #199(모델 버전 관리 원칙) — 사람마다 12주를 시작한 모델 버전으로 끝까지 계산, 다음 12주는 새 버전으로 시작하고 안내.

## 1. 12주(프로그램) 단위

| 항목 | 규칙 |
|---|---|
| 용어 | 12주 = 프로그램, 4주 = 사이클. 프로그램 하나에 사이클 3개 |
| `GET /challenges/cycles` | 각 항목에 `program_number`(1, 2, …) 추가. **`cycle_number`는 프로그램 안에서 1~3으로 유지**(4, 5, 6으로 이어 가지 않음) — 화면의 "N차"가 그대로 맞음 |
| 정렬 | 지금처럼 최신순 |
| `program_number` 없는 응답 | 프론트가 사이클 번호 3개씩 묶어 12주 1개로 봄(지금 동작) |

## 2. 새 12주 시작

| 항목 | 규칙 |
|---|---|
| `GET /challenges/program/status` (신규) | 지금(가장 최근) 12주의 상태. 아래 필드 |
| `POST /challenges/program/restart` (신규) | 12주를 마친 사람만. 새 프로그램을 만들고 `program_number`를 1 올림. 응답은 status와 같은 모양. 마친 게 아니면 **409 `PROGRAM_NOT_COMPLETE`** |
| 기존 `CHALLENGE_PROGRAM_COMPLETE`(409) | 새 12주를 만들기 전에 사이클을 시작하려 할 때만. restart 뒤에는 정상 시작 |
| 이전 12주 | 덮어쓰지 않고 그대로 보존(사이클·결과·예측·모델 버전) |

`status` 응답 필드

```json
{
  "program_number": 1,
  "complete": true,
  "can_restart": true,
  "model_version": "v0.1.1",
  "latest_model_version": "v0.2.0",
  "version_changed": true,
  "latest_updated_on": "2026-10-20",
  "change_note": "한국인 보정 확률 기준"
}
```

- `can_restart`: 12주를 마쳤고 새 12주를 시작할 수 있을 때 true. **이 값이 true일 때만 홈에 "새 12주 시작하기" 버튼이 보임**
- `model_version`: 이 사람이 지금 12주에 쓰는(시작 때 고정된) 버전
- `latest_model_version`/`latest_updated_on`/`change_note`: 새 12주에 적용될 최신 버전과 날짜, 바뀐 점(한 줄). `version_changed`는 두 버전이 다르면 true
- 12주를 아직 안 마쳤으면 `complete: false`, `can_restart: false`

프론트 동작: 버튼 → 확인창에 "이번 12주부터 새 분석 모델(v○.○, ○○ 업데이트)이 적용돼요. 바뀐 점: …" → 확인하면 `restart` 호출 → 챌린지 선택 화면.

## 3. 모델 버전 표시

| 위치 | 필요한 응답 | 프론트 표시 |
|---|---|---|
| 결과 화면 | 예측 결과 `model_a`/`model_b`의 `model_version`(이미 있음), `model_updated_on`(**추가**, 날짜) | 아래쪽 안내에 "분석 모델: 심장 혈관 건강 신호 v○ (날짜 업데이트) · 생활습관·체형 비교 v○" |
| 12주 결과 `GET /challenges/program/review` | `model_version`, `model_updated_on` 추가. `?program=N`으로 지난 12주 지정(없으면 최근) | "분석 모델 v○. 이 결과는 12주를 시작한 모델 그대로 처음부터 끝까지 계산했어요" |
| 지난 12주 기록 | 사이클 목록의 `program_number` | 지난 12주 항목을 누르면 `program-review.html?program=N` |

## 4. 사람별 모델 고정 (서버)

- 12주 첫 분석 때 그 사람이 쓴 모델 버전을 저장하고, 4주·12주 비교·재계산은 모두 그 버전으로 계산(모델 파일을 버전별로 읽음)
- 새 12주를 시작할 때 최신 버전으로 갱신
- 안전 문제·버그로 전원을 즉시 새 버전으로 바꿀 때는 고정과 상관없이 바꾸고, `status.version_changed`/`change_note`로 화면에 알림(공지는 별도)

## 5. 아직 안 만든 것

- **이전 12주 ↔ 새 12주 비교 화면**: 만들지 않았어요. 필요해지면 두 12주의 `model_version`이 다를 때 "모델이 달라 직접 비교할 수 없어요"를 보여 줄 거예요(4주 비교에는 이미 같은 안내가 있음, `reason: model_version_changed`)
- **공지·푸시**: 새 버전 배포 전 공지(무엇이 바뀌는지, 언제부터)는 관리자 공지 화면으로 올리면 돼요. 푸시로도 보내려면 알림 종류에 "공지"를 추가해야 하고, 담당을 정해야 해요
- 정의서 CHAL-012("서버는 12주를 한 번만 허용")는 이 기능이 들어가면 고쳐야 해요

## 6. 확인할 것 (서버 PR 기준)

1. `cycle_number`가 프로그램 안에서 1~3인지(4부터 이어지지 않는지)
2. 12주를 안 마친 사람이 `restart`를 호출하면 409
3. restart 뒤 이전 12주의 결과·모델 버전이 그대로인지
4. `status.can_restart`는 12주를 마친 직후에만 true, 시작하면 false

## 서버 구현 확인 (PR #200, 혜림, 2026-10-26)

위 규칙과 서버 구현을 대조했어요. 필드 이름과 오류 코드가 그대로 맞아서 프론트는 응답 모양을 바꾸지 않았어요.

| 항목 | 서버 (PR #200) | 프론트 |
|---|---|---|
| 사이클 목록 | `program_number` 추가, 새 12주에서 `cycle_number`가 1차부터 다시 시작 | 12주별로 묶어 "N번째 12주"로 표시 |
| `GET /challenges/program/status` | `program_number`, `complete`, `can_restart`, `model_version`, `latest_model_version`, `version_changed`, `latest_updated_on`, `change_note`(그 밖에 `model_a_version`·`model_b_version`은 무시). 시작한 12주가 없으면 404 `PROGRAM_NOT_FOUND` | 못 불러오면 새 12주 버튼을 숨겨요 |
| `POST /challenges/program/restart` | 마친 12주가 없으면 409 `PROGRAM_NOT_COMPLETE`, 성공하면 status와 같은 모양으로 새 프로그램 정보 | 확인창을 거쳐 호출 뒤 챌린지 선택으로 이동, 실패하면 확인창에 오류 사유 |
| `GET /challenges/program/review?program=N` | `program_number`, `model_version`, `model_updated_on` 추가 | 지난 12주를 누르면 `?program=N`으로 열고 "분석 모델 v○" 표시, 2번째 이후는 제목에 "N번째" |
| 예측 결과 | 모델 결과에 `model_updated_on` 추가 | 결과 화면의 "분석 모델" 줄에 업데이트 날짜 표시 |

프론트 보완(10/26): 새 12주를 시작했지만 아직 4주를 시작하지 않은 홈에 "N번째 12주를 시작했어요" 카드를 보여 줘요.

배포 순서(서버): 백엔드 코드 반영 → `alembic upgrade head` → 서버 재시작. 기존 챌린지 기록은 자동으로 프로그램 1에 연결돼요. 프론트는 서버 응답이 없어도 기존 동작이라 서버보다 먼저 나가도 돼요.
