### 규제 문서가 직접 요구하는 것과 우리 판단의 구분

- **직접 요구:** 변경 계획을 미리 세우기, 버전 표시, 사용자 안내(2·3·5번)
- **규제상 허용되는 방식 중 우리가 고른 것:** 사람별 시작 버전 고정(1번). 세 문서 모두 진행 중인 사용자를 고정하라고도, 고정할 필요 없다고도 쓰지 않음. 오히려 업데이트가 기존 사용자에게 적용될 수 있다고 보고(FDA 14쪽), 여러 버전이 동시에 쓰이는 경우도 전제함(FDA 28쪽). 고정을 고른 이유는 12주 전후 비교가 생활습관 변화를 보여 주려면 같은 모델이어야 하기 때문임.
- **해석·사례:** 과거 결과 보존(4번)

### 구현 순서

**백엔드**

1. `app/ml/predictor.py`가 모델 파일을 버전별로 읽게 함 (`model_a_v0.1.1.json`은 이미 저장소에 있음).
2. 분석할 때 그 사람의 프로그램 첫 분석 버전을 찾아 그 버전으로 계산함.
3. 비교는 같은 버전끼리라 다시 계산할 필요 없음. `current_version_view`는 안전 문제로 교체한 경우처럼 고정할 수 없을 때만 씀.
4. 결과 응답에 `model_version`과 그 버전의 업데이트 날짜를 내려줌.

**프론트**

1. 결과 화면에 지금 적용된 모델 버전과 업데이트 날짜를 표시함 (원칙 2번).
2. 다음 12주 시작 화면에서 버전이 바뀌었으면 안내함 (원칙 5번). 예: "이번 12주부터 새 분석 모델(v○.○)이 적용돼요. 바뀐 점: …" ("바뀐 점"은 버전마다 채움)
3. 첫 12주와 다음 12주를 비교하는 화면이 있으면, 버전이 다를 때 "모델이 달라 직접 비교할 수 없어요" 안내 (추가 규칙).

**공지 (담당 미정)**

1. 새 버전 배포 전에 공지사항 또는 푸시로 무엇이 바뀌는지와 언제부터 적용되는지 알림 (원칙 2번).
2. 안전 문제·버그로 전원 즉시 교체할 때도 같은 방법으로 알림 (예외 규칙).

### 현재 코드 근거

`modeling/paeon_models.py:20`(서버가 읽는 모델 파일 v0.2.0), `app/services/prediction_job_service.py:233`(`current_version_view`)·`:332`, `app/services/challenge_service.py:495`, `tests/test_model_compare.py`·`tests/test_program_review.py`(6개 통과, 2026-10-26)

### 열린 질문

- 식약처 의료기기 해당 여부 질의 답변 대기중. 의료기기로 판정되면 변경관리 계획서는 허가 신청 서류가 됨. 웰니스로 판정되면 아래 문서들은 의무가 아닌 참고 기준이 됨.
