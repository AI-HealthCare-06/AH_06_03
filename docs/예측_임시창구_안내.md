# 예측 임시 창구(`/v1/predict`) 안내

> 작성: 혜림(백엔드) · 대상: 팀 전체
> 한 줄 요약: **건강 정보를 넣으면 모델 A·B 결과를 바로 돌려주는 연습용 창구**를 만들었어요.

---

## 1. 무엇을 만들었나요?

앱 화면(프론트)과 예측 모델 사이에 **주문 창구**를 하나 만들었어요.

```
이슬님 화면  ──주문서(건강 정보)──▶  /v1/predict 창구  ──▶  모델 A·B
            ◀──결과지(예측 결과)──
```

- 주소: **`POST /v1/predict`**
- 지금까지 데모는 화면 안에서 **가짜 계산**을 했는데, 이제 이 창구로 **진짜 모델 결과**를 받을 수 있어요.

## 2. 왜 "임시"예요?

API 명세서에 적힌 **정식 방식**은 이래요.

```
1. 건강기록 저장        POST /health/records
2. 예측 신청 → 번호표   POST /predictions/jobs
3. 번호표로 결과 확인   GET  /predictions/jobs/{job_id}
```

식당 진동벨처럼, 주문하면 번호표를 먼저 받고 결과는 나중에 찾아가는 방식이에요. 이걸 하려면 **로그인과 DB**가 먼저 있어야 해서 시간이 걸려요.

그래서 멘토님 조언대로 **작은 것부터** 시작했어요. 정식 방식이 완성될 때까지 이 임시 창구로 먼저 연결하고, 완성되면 임시 창구는 지울 거예요.

> 지금 만든 코드는 버려지지 않아요. 모델을 부르는 부분은 정식 방식에서도 그대로 써요. 바뀌는 건 **손님 받는 방식(창구)** 뿐이에요.

## 3. 안에서는 어떻게 돌아가요?

파일 4개가 식당처럼 일을 나눠요.

| 파일 | 식당으로 치면 | 하는 일 |
|---|---|---|
| `app/apis/prediction.py` | 창구 직원 | 주문을 받고 결과를 돌려줘요. 계산은 안 해요 |
| `app/schemas/prediction.py` | 주문서 양식 | 잘못 쓴 주문서를 입구에서 돌려보내요 (422) |
| `app/services/prediction_service.py` | 매니저 | 모델 A·B를 **따로** 불러요. 한쪽이 고장 나도 다른 쪽 결과는 살려요 |
| `app/ml/predictor.py` | 주방 가는 복도 | `modeling/paeon_models.py`를 부르는 유일한 통로예요 |

**중요한 원칙 두 가지**
- 모델 코드(`paeon_models.py`)는 **고치지 않았어요.** 우리가 모델에 맞췄어요.
- 모델이 준 결과는 **가공하지 않고 그대로** 전달해요. 두 모델 점수를 합치지도 않아요.

## 4. 직접 해 보기

1. 저장소 최상위 폴더에서 서버 켜기
   ```
   uvicorn app.main:app --reload
   ```
2. 브라우저에서 `http://127.0.0.1:8000/docs` 열기
3. `POST /v1/predict` → **Try it out** → 아래 내용 붙여 넣기 → **Execute**

```json
{
  "age": 45, "sex": "M", "height_cm": 172, "weight_kg": 78, "waist_cm": 88,
  "sbp": 145, "dbp": 92, "total_chol": 212, "smoking": "current", "diabetes": false,
  "htn_status": "none", "parent_htn": "yes", "drink_freq": "2_3_per_week", "drink_amount": "5_6",
  "breakfast": "1_2", "eatout": "1_per_day", "moderate_min_per_week": 60, "vigorous_min_per_week": 0
}
```

결과는 **Server response → Response body**에 이런 모양으로 나와요.

```json
{
  "data": {
    "model_a": { "status": "completed", "probability": 0.15..., "risk_level": "borderline", ... },
    "model_b": { "status": "completed", "probability": 0.53..., "risk_level": null, ... },
    "disclaimer": "이 결과는 진단이 아닌 선별 정보입니다. ..."
  }
}
```

- 입력 칸 이름과 값은 `modeling/handoff/모델_연결_명세.md` §1과 **글자 하나까지 똑같아야** 해요.
- 틀리면 **422**가 오고, `detail` 안의 `loc`에 틀린 칸 이름이 나와요.

## 5. 테스트 결과

`modeling/handoff/test_cases.json`의 가상 사용자로 확인했어요. 모두 정답과 같게 나왔어요.

| 테스트 | 어떤 경우 | 모델 A | 모델 B |
|---|---|---|---|
| T1 | 둘 다 계산 | 계산됨 (경계) | 계산됨 |
| T3 | 혈압약 복용 중 | 계산됨 (위험) | **건너뜀** (`htn_diagnosed`) |
| T5 | 27세 | **건너뜀** (`age_out_of_range`) | 계산됨 |
| T6 | 빈칸 있음 | 계산됨 (정상) | 계산됨, 빈칸 6개 알림 |

"건너뜀"은 오류가 아니에요. 모델이 **대상이 아닌 사람**에게는 규칙대로 대답하지 않는 거예요.

## 6. 이슬님(프론트)께

**연결 방법**: 데모의 가짜 계산(`X()`, `risk()`) 대신 이렇게 주문을 넣으면 돼요.

```javascript
const res = await fetch("http://127.0.0.1:8000/v1/predict", {
  method: "POST",
  headers: { "Content-Type": "application/json" },
  body: JSON.stringify(user),   // 명세 §1 형식
});
const { data } = await res.json();   // data.model_a, data.model_b, data.disclaimer
```

**화면에서 꼭 처리해야 할 것**

1. **입력 선택지를 명세대로 바꾸기**
   명세 §1.3 "데모와 다른 점" 표를 봐 주세요. 흡연 3단계, 음주 빈도 7단계, 허리둘레·한 번 음주량 추가 등이 있어요.
2. **1등 요인이 비어 있을 수 있어요**
   위험을 높인 요인이 하나도 없으면 `top_risk_factor`가 `null`이에요 (T6 모델 A). 빈칸일 때 보여줄 문구가 필요해요.
3. **빈칸을 채운 값이 요인으로 나와요**
   사용자가 허리둘레를 안 적어도 요인 목록에 `허리둘레 81.1`이 나올 수 있어요 (T6 모델 B). `missing_features`에 있는 요인은 빼거나 "입력하지 않음"으로 보여 주세요. 부모 가족력 "모름"도 빈칸으로 처리돼요.
4. **거꾸로 배운 요인이 있어요**
   모델 B에서 흡연·외식 등이 "위험을 **낮춘** 요인"으로 나올 수 있어요 (T5). `direction_matches_expectation`이 `false`인 요인이에요. 화면에 강조하지 않는 게 좋아요.
5. **모델 A 확률(%)은 그대로 보여주지 않기**
   미국 옛날 데이터라 숫자가 부풀려져 있어요. `risk_level`(정상·경계·위험)로만 보여 주세요.
6. **오류 모양은 나중에 바뀌어요**
   지금은 `{"detail": [...]}`이고, 명세서 규칙(`{"error": {...}}`)으로 곧 바꿀 예정이에요.

**아직 안 된 것**: 이슬님 화면 주소에서 요청을 받아 주는 설정(CORS)을 곧 추가할게요. 연결했는데 브라우저에 `blocked by CORS policy`가 뜨면 알려 주세요. 화면을 어느 주소에서 켜는지 알려 주시면 그 주소를 허락 목록에 넣을게요.

## 7. 효민님(배포 · API 명세서)께

**배포**


- **실행 명령**: 저장소 최상위에서 `uvicorn app.main:app`
- **새로 설치할 도구 없음**: FastAPI·Pydantic만 쓰고, 모델 파일은 파이썬 기본 기능만 써요.
- ⚠️ **`modeling/` 폴더도 Docker 이미지에 꼭 넣어 주세요.**
  `app/ml/predictor.py`가 `modeling/paeon_models.py`와 계수 파일(`modeling/model_*/artifacts/*.json`)을 읽어요. `app/`만 복사되면 서버가 `No module named 'paeon_models'`로 멈춰요.
- 서버에 올라가면 새 주소를 알려 주세요. CORS 허락 목록과 이슬님 연결 주소를 바꿔야 해요.

**API 명세서 확인 부탁**

1. 이 임시 창구(`/v1/predict`)는 명세서에 없는 창구예요. 정식 흐름이 완성되면 지울 예정인데, 그동안 써도 괜찮을까요?
2. 명세서와 ERD가 다른 곳이 있어요.
   - 예측 요청 종류: 명세서 `auto/manual` ↔ ERD `initial/interim/full/manual`
   - 선택 항목 미입력: 명세서는 `input_method=incomplete_input`인데, ERD에서 `incomplete_input`은 **결과 고지 유형**(`disclosure_type`)이에요
   - 흡연·음주 분류: 명세서는 "설문 응답으로 산출"인데, 정의서 v1.8부터는 **건강정보 입력(W04)** 기준이에요
