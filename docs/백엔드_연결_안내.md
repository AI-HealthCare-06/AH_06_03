# 파이온 백엔드 연결 안내

> 작성: 혜림(백엔드) · 대상: 프론트엔드
> 화면에서 **언제 어느 창구를 부르고, 무엇을 보내고, 무엇을 받는지** 정리한 문서예요.
> 직접 눌러 보려면 서버를 켜고 `http://127.0.0.1:8000/docs`를 열면 돼요.

---

## 0. 먼저 알아 둘 것

### 주소

| 환경 | 기본 주소 |
|---|---|
| 내 컴퓨터 | `http://127.0.0.1:8000` |
| EC2 서버 | 효민님께 받은 주소 |

모든 창구 주소는 **`/v1`**로 시작해요. 예: `http://127.0.0.1:8000/v1/auth/login`

### 응답 모양 (모든 창구 공통)

```json
// 성공
{"data": { ... }}

// 실패
{"error": {"code": "AUTH_EMAIL_DUPLICATED", "message": "이미 가입된 이메일입니다."}}
```

- 성공하면 결과는 항상 **`data`** 안에 있어요. → `res.data`
- 실패하면 **`error.code`로 분기**하고, `error.message`는 그대로 화면에 보여 줘도 되는 한국어예요.
- 예외: 로그아웃은 성공하면 **204**, 응답 내용이 없어요.

### 로그인이 필요한 창구

🔒 표시가 있는 창구는 헤더에 **팔찌(access token)**를 붙여서 보내요.

```javascript
fetch(`${BASE}/v1/users/me`, {
  headers: { "Authorization": `Bearer ${accessToken}` },
});
```

- 팔찌(`access_token`)는 **30분**, 쿠폰(`refresh_token`)은 **14일** 유효해요.
- 팔찌가 만료되면 401 `AUTH_TOKEN_EXPIRED`가 와요. → [5. 쿠폰 재발급](#5-쿠폰-재발급--로그아웃)으로 새 팔찌를 받고 **같은 요청을 다시** 보내요.

### CORS

`http://localhost:5500`, `http://127.0.0.1:5500`에서 오는 요청을 허락해 뒀어요. 다른 주소에서 화면을 켜면 알려 주세요.

## 1. 화면 흐름 한눈에 보기

```
① 회원가입        POST  /v1/auth/signup
② 로그인          POST  /v1/auth/login                      → 팔찌 + 쿠폰
③ 성별 입력 🔒     PATCH /v1/users/me
④ 검진 상자 🔒     POST  /v1/health/records                   → health_record_id
⑤ 측정값 🔒       POST  /v1/health/records/{id}/measurements
⑥ 문제지 🔒       GET   /v1/surveys/initial_lifestyle/active
⑦ 답안지 🔒       POST  /v1/survey-instances                   → survey_instance_id
⑧ 답 적기 🔒      POST  /v1/survey-instances/{id}/responses   (여러 번 가능)
⑨ 제출 🔒         POST  /v1/survey-instances/{id}/submit
⑩ 예측 🔒         POST  /v1/predictions/jobs
⑪ 최근 결과 🔒     GET   /v1/predictions/latest
```

**순서에서 꼭 지킬 것**
- 예측(⑩) 전에 **성별(③)**이 있어야 해요. 없으면 422 `PREDICTION_SEX_REQUIRED`.
- 설문은 **제출(⑨)한 것만** 예측에 쓰여요.

## 2. 회원 · 인증

### ① 회원가입 `POST /v1/auth/signup`

```json
{"email": "hyerim@a.com", "password": "mypassword1", "birth_date": "2000-05-10"}
```

| 칸 | 규칙 |
|---|---|
| `email` | 이메일 형식. 대소문자 구분 없음 (서버가 소문자로 저장) |
| `password` | 8~72자 |
| `birth_date` | `YYYY-MM-DD` |

**성공 201**

```json
{"data": {"user_id": "01a0f54f-...", "guardian_verification_status": null}}
```

**만 14세 미만**은 보호자 정보 세 칸을 **같이** 보내야 해요. 세 칸은 **다 채우거나 다 비워야** 해요(일부만 채우면 422).

```json
{
  "email": "kid1@a.com", "password": "mypassword1", "birth_date": "2015-01-01",
  "guardian_name": "김보호", "guardian_relation": "parent", "guardian_contact": "010-1234-5678"
}
```

- `guardian_relation`: `parent` / `legal_guardian`
- `guardian_contact`: 휴대폰 번호 또는 이메일
- 성공하면 `"guardian_verification_status": "pending"` → "보호자 확인을 기다리고 있어요" 안내를 띄워 주세요.
- 보호자 확인 전에는 **로그인할 수 없어요**(403 `AUTH_GUARDIAN_PENDING`). 보호자 확인 기능은 다음 사이클 예정이에요.

### ② 로그인 `POST /v1/auth/login`

```json
{"email": "hyerim@a.com", "password": "mypassword1"}
```

**성공 200**

```json
{
  "data": {
    "access_token": "eyJhbGciOi...",
    "refresh_token": "Xk9_...",
    "token_type": "bearer",
    "expires_in": 1800
  }
}
```

- `access_token`, `refresh_token`을 둘 다 **저장**해 두세요.
- 이메일이 없든 비밀번호가 틀리든 **똑같이** 401 `AUTH_INVALID_CREDENTIALS`예요.

### ③ 성별 입력 🔒 `PATCH /v1/users/me`

W04에서 성별을 받으면 보내요.

```json
{"sex": "male"}
```

- `male` / `female`만 받아요. (`M`, `F`는 422)

### 내 정보 🔒 `GET /v1/users/me`

```json
{"data": {"user_id": "...", "email": "hyerim@a.com", "sex": "male", "birth_date": "2000-05-10"}}
```

## 3. 건강기록

검진 **한 번**은 **상자**(`health_records`), 그 안의 혈압·키·몸무게 **하나하나**는 **물건**(`measurements`)이에요. 상자를 먼저 만들고, 물건을 넣어요.

### ④ 상자 만들기 🔒 `POST /v1/health/records`

```json
{"input_type": "initial", "examination_date": "2026-10-01"}
```

| `input_type` | 뜻 |
|---|---|
| `initial` | 처음 검진 |
| `interim_reassessment` | 4주 재평가 |
| `full_reassessment` | 3~6개월 전체 재검진 |
| `weekly_bp` | 주간 혈압 기록 |
| `manual` | 직접 추가 |

**성공 201** → `health_record_id`를 기억해 두세요.

```json
{"data": {"health_record_id": "...", "input_type": "initial", "examination_date": "2026-10-01"}}
```

- 같은 사람이 **같은 종류·같은 날짜** 상자를 또 만들면 409 `HEALTH_RECORD_DUPLICATED`.

### ⑤ 물건 넣기 🔒 `POST /v1/health/records/{health_record_id}/measurements`

```json
{
  "measurements": [
    {"metric_code": "SBP", "value_num": 145},
    {"metric_code": "DBP", "value_num": 92},
    {"metric_code": "HEIGHT", "value_num": 172},
    {"metric_code": "WEIGHT", "value_num": 78},
    {"metric_code": "WAIST", "value_num": 88},
    {"metric_code": "TOTAL_CHOL", "value_num": 212},
    {"metric_code": "HDL", "value_num": 48},
    {"metric_code": "SMOKING", "value_code": "current"},
    {"metric_code": "DIABETES", "value_code": "false"},
    {"metric_code": "HTN_STATUS", "value_code": "none"},
    {"metric_code": "PARENT_HTN", "value_code": "yes"},
    {"metric_code": "ALCOHOL_FREQ", "value_code": "2_3_per_week"},
    {"metric_code": "ALCOHOL_AMOUNT", "value_code": "5_6"}
  ]
}
```

**성공 201** → 넣은 물건 목록이 와요. **BMI가 하나 더** 들어 있어요(서버가 계산, `input_method: "calculated"`).

#### 지표 코드표

**재는 값**은 `value_num`(숫자), **고르는 값**은 `value_code`(글자)로 보내요. 한 물건에는 **둘 중 하나만** 보내요.

| 코드 | 칸 | 허용 값 / 단위 | 필수 |
|---|---|---|---|
| `SBP` | `value_num` | mmHg (수축기혈압) | ✅ |
| `DBP` | `value_num` | mmHg (이완기혈압) | ✅ |
| `HEIGHT` | `value_num` | cm | ✅ |
| `WEIGHT` | `value_num` | kg | ✅ |
| `WAIST` | `value_num` | cm (허리둘레) | ✅ |
| `TOTAL_CHOL` | `value_num` | mg/dL | ✅ |
| `HDL` | `value_num` | mg/dL | ✅ |
| `FASTING_GLUCOSE` | `value_num` | mg/dL | 선택 |
| `SMOKING` | `value_code` | `current` / `former` / `never` | ✅ |
| `DIABETES` | `value_code` | `true` / `false` (**글자**로) | ✅ |
| `HTN_STATUS` | `value_code` | `none` / `diagnosed_untreated` / `treated` | ✅ |
| `PARENT_HTN` | `value_code` | `yes` / `no` / `unknown` | ✅ |
| `ALCOHOL_FREQ` | `value_code` | `never_lifetime` / `none_past_year` / `lt_monthly` / `monthly` / `2_4_per_month` / `2_3_per_week` / `4plus_per_week` | ✅ |
| `ALCOHOL_AMOUNT` | `value_code` | `1_2` / `3_4` / `5_6` / `7_9` / `10plus` | 음주자만 |

- 코드는 **대문자**, 범주 값은 표에 적힌 그대로예요. 선택지 문구는 `modeling/handoff/모델_연결_명세.md` §1.2를 보세요.
- **단위는 안 보내도 돼요.** 서버가 채워요.
- **BMI는 보내지 마세요.** 서버가 키·몸무게로 계산해요. 보내면 422.
- `ALCOHOL_FREQ`가 `never_lifetime`·`none_past_year`면 `ALCOHOL_AMOUNT`는 **묻지도 보내지도** 않아요.
- 코드표 원본: `app/services/health_service.py`의 `METRICS`

#### 일부만 보내도 되나요?

- **저장은 1개 이상이면 돼요.** 같은 상자에 **나눠서 여러 번** 보내도 돼요.
- 이미 넣은 지표를 **또 보내면** 409 `HEALTH_MEASUREMENT_DUPLICATED`.
- **서버는 필수 지표를 막지 않아요.** 빈 값은 예측할 때 중간값으로 채워지고 정확도가 떨어져요. 그래서 위 표의 **필수 ✅는 화면에서 막아 주세요.**

## 4. 생활습관 설문

시험처럼 **문제지 받기 → 답안지 받기 → 답 적기 → 제출** 순서예요.

### ⑥ 문제지 받기 🔒 `GET /v1/surveys/initial_lifestyle/active`

```json
{
  "data": {
    "survey_version_id": "01a0f900-0000-7000-8000-000000000001",
    "survey_type": "initial_lifestyle",
    "version": "v1",
    "questions": [
      {
        "question_id": "01a0f900-0000-7000-8001-000000000001",
        "question_code": "BREAKFAST",
        "question_text": "최근 1년 동안 아침 식사를 일주일에 몇 번 하셨나요?",
        "required": true,
        "options": [
          {"option_id": "...", "option_code": "5_7", "option_text": "주 5~7회"}
        ]
      }
    ]
  }
}
```

- 질문은 **순서대로** 와요. 받은 그대로 화면에 그리면 돼요.
- 질문 문장을 바꾸고 싶으면 백엔드에 알려 주세요. **화면 코드는 안 고쳐도** 돼요.
- 지금 질문: 아침 식사(`BREAKFAST`), 외식·배달(`EATOUT`), 유산소 운동(`AEROBIC`). 나트륨 설문(`sodium`)은 아직 없어요(404).

### ⑦ 답안지 받기 🔒 `POST /v1/survey-instances`

```json
{"survey_version_id": "01a0f900-0000-7000-8000-000000000001", "health_record_id": "④의 번호(선택)"}
```

**성공 201** → `survey_instance_id`를 기억해 두세요.

```json
{"data": {"survey_instance_id": "...", "survey_version_id": "...", "status": "started"}}
```

### ⑧ 답 적기 🔒 `POST /v1/survey-instances/{survey_instance_id}/responses`

```json
{
  "responses": [
    {"question_id": "아침 질문 번호", "option_id": "고른 보기 번호"},
    {"question_id": "외식 질문 번호", "option_id": "고른 보기 번호"}
  ]
}
```

- 질문마다 **보기 하나**만 골라요.
- **제출 전에는** 같은 질문을 다시 보내면 **새 답으로 바뀌어요.** 한 질문씩 보내도 되고, 한 번에 다 보내도 돼요.
- 다른 질문의 보기를 보내면 422 `SURVEY_OPTION_INVALID`.

### ⑨ 제출 🔒 `POST /v1/survey-instances/{survey_instance_id}/submit`

보낼 내용 없음.

- 필수 질문이 비어 있으면 422 `SURVEY_INCOMPLETE`. 메시지에 빠진 질문 코드가 들어 있어요. 예: `"답하지 않은 필수 질문이 있습니다: AEROBIC"`
- 제출하면 `"status": "submitted"`. 그 뒤에는 답을 고칠 수 없어요(409 `SURVEY_ALREADY_SUBMITTED`).

## 5. 예측

### ⑩ 예측하기 🔒 `POST /v1/predictions/jobs`

```json
{"health_record_id": "④의 번호", "survey_instance_id": "⑦의 번호(선택)"}
```

- `survey_instance_id`를 안 보내면 **가장 최근에 제출한** 설문을 써요. 제출한 설문이 없어도 예측은 돼요.
- `request_type`(선택): `initial`(기본) / `interim` / `full` / `manual`

**성공 201**

```json
{
  "data": {
    "prediction_job_id": "...",
    "status": "completed",
    "model_a": {
      "model_code": "MODEL_A",
      "model_version": "0.1.1",
      "status": "completed",
      "probability": 0.150995,
      "risk_level": "borderline",
      "vascular_age": 48.7,
      "factors": [ ... ],
      "top_risk_factor": { ... },
      "top_modifiable_factor": { ... },
      "missing_features": []
    },
    "model_b": {
      "model_code": "MODEL_B",
      "status": "completed",
      "probability": 0.533,
      "risk_level": null,
      ...
    },
    "disclaimer": "이 결과는 진단이 아닌 선별 정보입니다. ..."
  }
}
```

모양은 예전 임시 창구(`/v1/predict`) 결과에 `prediction_job_id`, `status`만 더한 거예요.

### ⑪ 최근 결과 다시 보기 🔒 `GET /v1/predictions/latest`

⑩ 결과와 **똑같은 모양**이에요. 대시보드에 쓰면 돼요. 예측한 적이 없으면 404 `PREDICTION_NOT_FOUND`.

### 결과를 화면에 보여 줄 때 꼭 지킬 것

자세한 이유는 `modeling/handoff/데이터_특성.md`를 보세요.

| 항목 | 지킬 것 |
|---|---|
| 모델 A `probability` | **% 숫자로 보여 주지 말기.** `risk_level`(정상·경계·위험)로만 |
| 모델 A가 예측하는 것 | 10년 내 **관상동맥질환** 위험. "고혈압 발생"이라고 쓰지 않기 |
| `vascular_age` | **"혈관 나이(추정)"**로 표기. 실제 나이와 차이를 단정적으로 강조하지 않기 |
| 모델 B | **판정 없음**(`risk_level`이 항상 `null`). "현재 경계군과 닮은 정도"로만 표현 |
| 두 모델 점수 | **합치거나 평균 내지 않기** |
| `status: "skipped"` | 오류 아님. `skip_reason`으로 안내 (`age_out_of_range`: 나이 범위 밖, `htn_diagnosed`: 고혈압 진단·치료 중이라 모델 B 제외) |
| `top_risk_factor` | `null`일 수 있어요 (위험을 올린 요인이 없을 때). 빈칸 문구 준비 |
| `missing_features` | 여기 있는 요인은 **빈칸을 채운 값**이에요. 요인 목록에서 빼거나 "입력하지 않음"으로 표시하고, "정확도 한계" 안내 |
| `direction_matches_expectation: false` | 모델 B가 **상식과 반대로 배운** 요인(흡연·외식·운동). 화면 강조는 피하기 |
| `disclaimer` | 결과 화면에 **항상** 보여 주기 |

## 6. 쿠폰 재발급 · 로그아웃

### 쿠폰 재발급 `POST /v1/auth/token/refresh`

팔찌가 만료됐을 때(401 `AUTH_TOKEN_EXPIRED`) 불러요. **팔찌 없이** 보내요.

```json
{"refresh_token": "저장해 둔 쿠폰"}
```

**성공 200** → 로그인 결과와 같은 모양으로 **새 팔찌 + 새 쿠폰**이 와요.

- ⚠️ **새 `refresh_token`으로 꼭 바꿔 저장하세요.** 쓴 쿠폰은 버려져서 다시 쓰면 401이에요.
- 401 `AUTH_INVALID_REFRESH_TOKEN`이 오면 → 로그인 화면으로.

**추천 흐름**

```
요청 → 401 AUTH_TOKEN_EXPIRED
     → POST /v1/auth/token/refresh (쿠폰)
         ├ 200 → 새 팔찌·쿠폰 저장 → 원래 요청 다시 보내기
         └ 401 → 로그인 화면으로
```

### 로그아웃 🔒 `POST /v1/auth/logout`

```json
{"refresh_token": "저장해 둔 쿠폰"}
```

- 성공하면 **204**, 응답 내용 없음.
- 화면에서는 저장해 둔 **팔찌와 쿠폰을 지워** 주세요.

## 7. 오류 코드표

### 422: 두 종류

```json
// ① 양식 검사 실패 → details에 어느 칸인지
{"error": {"code": "VALIDATION_ERROR", "message": "입력값을 확인해 주세요.",
           "details": [{"field": "email", "reason": "value is not a valid email address..."}]}}

// ② 서버 판단 → details 없음
{"error": {"code": "HEALTH_METRIC_UNKNOWN", "message": "WIEGHT: 알 수 없는 지표입니다."}}
```

①은 `details[].field`를 보고 **해당 입력칸**에 오류를 표시하면 돼요.
