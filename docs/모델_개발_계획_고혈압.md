### 1-1. 서비스 흐름과 모델 역할 🟡 (모델링 제안 · 9/28 회의에서 공유)

```
① 검진값 입력
      ↓
② 현재 상태 판정 = 입력 혈압 규칙 (모델 아님)
   · 정상 / 경계군(주의혈압·고혈압전단계)
   · 140/90 이상 + 미진단 → 검사·상담 권고 (REQ-PRED-005)
      ↓
③ 모델 A (Framingham) → 10년 관상동맥질환 위험을 상대 위험도(위험군·상위 %)로 제시 ※ 2차 버전
      ↓
④ 모델 B (국민건강영양조사, 혈압 제외 피처) → 사용자별 역할이 다름 (아래 표)
      ↓
⑤ 개선 가능한 1위 요인 → 챌린지 추천 (REQ-PRED-003, REQ-CHAL-008)
      ↓
⑥ 4주 후: 모델 B 재예측 + 실측 혈압 + 챌린지 달성률
   3~6개월 후: 전체 재검진 → 모델 A·B 재예측
```

**모델 B가 사용자별로 하는 일**
| 사용자 (② 판정) | 혈압 규칙만으로 | 모델 B가 더해주는 것 | 화면 문구 예 (사용자용 문구라 해요체 유지) |
|---|---|---|---|
| 혈압 정상 | "정상" | **경계군과 닮은 위험 프로필** — 나와 비슷한 사람 중 경계군 비율 | "나이·체형이 비슷한 한국인 중 ○%가 경계군이에요" |
| 혈압 경계군 | "경계군" | **어떤 요인이 위험을 높였는지** (SHAP) → 개선 가능 1위 요인 → 챌린지 | "위험을 높인 요인 중 바꿀 수 있는 1위는 허리둘레예요" |
| 혈압 모름 | 판정 불가 | 경계군 가능성 | "혈압을 재 보시길 권해요" + 가능성 |

- 예시 근거 (국민건강영양조사, 40대 남성, 정상+경계군): 허리둘레 85cm 미만 경계군 32% → 85–90cm 46% → 90cm 이상 **59%**
- 모델 B는 한 시점 조사라 **"닮았다·관련 있다"까지만** 말함. "앞으로 경계군이 된다", "허리둘레 때문에 경계군이 됐다"는 표현 금지 (NFR-SAFE-003)
- 4주 재예측 시 모델 B 입력 중 **허리둘레·체중(BMI)·음주·흡연**이 바뀌면 결과와 요인 기여도가 실제로 움직임 → 전후 비교에 사용

|---|---|---|---|

### 1-2. 개발 순서 🔄 (2026-09-28 멘토링 후 수정)

| 사이클 | 기간 | 범위 | 완료 기준 |

## 2. 모델을 A·B로 나눈 이유 ✅

한 데이터셋으로는 서비스가 필요로 하는 두 질문에 모두 답할 수 없음.

| | Framingham | KNHANES |
|---|---|---|
| 설계 | 미국 **코호트**(같은 사람을 10년 추적) | 한국 **횡단면**(한 시점 조사) |
| 할 수 있는 것 | 미래 위험 예측, 혈관 나이 | 한국인 기준 현재 상태, **식습관 변수**(나트륨·아침식사·외식) |
| 할 수 없는 것 | 식습관 설명(변수 없음), 한국인 대표성 | 미래 예측(추적 데이터 아님) |

**두 데이터를 합쳐 한 모델로 학습하지 않는 이유 (NFR-ML-007)**
1. 인구집단이 다름 — 미국 코호트와 한국 표본은 위험요인 분포가 다름
2. 라벨이 묻는 질문이 다름 — "10년 뒤 발생" vs "현재 상태"
3. 피처가 다름 — 합치면 서로 없는 변수가 대량 결측으로 채워짐

**결과를 한 점수로 합치지 않는 이유 (REQ-PRED-006)**
"10년 뒤 위험"과 "지금 생활·신체 위험 프로필"을 평균 내면 서로 다른 질문의 답이 섞여 사용자가 오해할 수 있음. 카드 2개로 분리하고, 성능표도 모델별로 따로 제시함.

### 3.1 연도 간 중복 대상자 ✅
- 제9기는 3년간 조사구 576개를 **연 192개씩 서로 다르게** 추출함 (이용지침서, 순환표본설계)
- 실제 데이터에서도 연도 간 겹치는 조사구(`psu`) 0개, 중복 `ID` 0건, 완전히 같은 행 0건
- → 연도 간 같은 사람이 중복될 가능성은 설계상 매우 낮고, 확인할 수 있는 범위에서도 중복 없음. **별도 제거 작업 불필요.**

### 3.2 같은 가구 구성원 — 학습/테스트 분할 시 주의 🟡 (필수 아님, 추가 권장)
- KNHANES는 표본 가구 안의 **가구원 전체**를 조사함 (이용지침서: 조사구당 25가구, 가구 내 1세 이상 모든 가구원)
- 가족은 식습관·가족력이 비슷함 → 같은 가족이 학습 세트와 테스트 세트에 나뉘어 들어가면 **성능이 실제보다 조금 좋게 나올 수 있음**
- 대응: 조사구(`psu`) 단위로 묶어서 분할 (`GroupKFold` / `GroupShuffleSplit`, `groups=psu`) → 같은 가구는 항상 같은 쪽에 들어감
- 병합 데이터에는 가구 ID 컬럼이 없어서 가구보다 큰 단위인 조사구로 묶음 (조사구 576개)
- 발표 시: 무작위 분할과 조사구 단위 분할 성능을 나란히 제시하면 "누수 점검" 근거로 쓸 수 있음 (NFR-ML-001, 평가 3-1)

## 부록. 2026-09-22 초안 (기록용)

> ⚠️ **이 부록은 실제 데이터를 확인하기 전에 쓴 초안임.** 이후 정정된 내용은 맨 위 **정정 대비표** 참고.

> 연결 요구사항: REQ-PRED-001~005 · NFR-ML-001~005
> 전제: 라벨 누수(label leakage) 방지 원칙 적용 (당뇨병 검토 시 논의된 원칙을 고혈압에 동일 적용)

### 1. 데이터셋 옵션 비교

| 데이터셋 | 규모 | 라벨 | 특징 |
|---|---|---|---|
| Hypertension Risk Prediction Dataset (Kaggle) | 174,982건, 24개 변수 | 고혈압 여부 (High/Low) | 건강·인구통계·생활습관 변수 포함, 규모 큼 |
| Cardiovascular Disease dataset (Kaggle) | 약 7만건 | 심혈관질환 여부 | 나이·성별·키·체중·수축기/이완기혈압·콜레스테롤·혈당·흡연·음주·운동 |
| **Framingham Heart Study (Kaggle)** | 약 4,238건 | **10년 뒤** 관상동맥질환(CHD) 발생 여부 | 오늘 혈압 → 미래 결과. **라벨 누수 없는 구조의 정석** |

#### 추천: Framingham 데이터셋

이유: 당뇨병 검토 때 논의한 문제(오늘 혈당을 피처로 쓰고 오늘 당뇨 여부를 라벨로 쓰면 순환정의가 되는 라벨 누수 문제)가
고혈압에도 동일하게 적용됨. Framingham 데이터셋은 애초에 **"오늘 혈압 → 10년 뒤 심혈관질환"**으로
라벨과 피처가 시간적으로 분리돼 있어서, 별도 설계 없이도 누수 걱정이 없는 구조임.

국내 데이터로는 질병관리청 **국민건강영양조사 원시자료**가 가장 이상적이나, 신청·승인 절차가 필요해
7주 일정 내 확보 리스크가 있음. 우선 Framingham으로 학습해두고, 서비스 운영 중 확보 가능하면
국내 데이터로 보강하는 방향으로 진행함.

### 2. 모델 구성

| 단계 | 모델 | 역할 |
|---|---|---|
| 베이스라인 | 로지스틱 회귀 | 해석 쉬움 — 어떤 변수가 위험을 얼마나 올리는지 계수로 바로 확인 가능 |
| 성능 모델 | 랜덤포레스트 또는 XGBoost / LightGBM | 표 형태 의료 데이터에서 성능이 가장 잘 나오는 계열 |
| 설명(XAI) | SHAP | 개별 사용자 예측을 요인별로 분해 — "이 사람은 나이·BMI·흡연이 위험을 얼마나 올렸는지" 개인화된 설명 제공. 이 결과가 그대로 챌린지 추천 근거(REQ-PRED-003)로 연결됨 |

**모델 비교**: 로지스틱회귀 vs XGBoost 등 2개 이상 모델을 비교하면 `NFR-ML-003`(모델 비교·평가지표 기록) 요구사항을 자연스럽게 충족함.

### 3. 피처 설계 (누수 방지 적용)

```
입력(피처): 나이, 성별, BMI, 허리둘레, 흡연여부, 음주빈도, 운동빈도, 가족력, (선택) 콜레스테롤
라벨: 10년 내 고혈압/심혈관질환 발생 여부 (Framingham 방식 — 라벨 시점이 피처 시점과 분리됨)
```

- 오늘 측정한 혈압 자체는 **모델 입력이 아니라 "결과 확인용 대시보드 지표"**로만 사용함
- 혈압을 모델에 포함하고 싶다면, "오늘 혈압(정상~경계 구간)"만 참고 피처로 넣고 진단 확정치로는 쓰지 않음

### 4. 사용자 입력값과 학습 데이터의 관계

혼동하기 쉬운 지점이라 별도로 정리함. **사용자가 W04(건강정보 입력)에서 입력하는 값**과
**모델을 학습시키는 데 쓰는 데이터**는 서로 다름.

```
[학습 단계]  Framingham 데이터셋(4,238건) → 로지스틱회귀/XGBoost 학습 → 모델 저장
                                              ↓
[서비스 단계] 사용자가 W04에서 본인 검진값 입력(직접 입력 또는 검진표 OCR 업로드)
              → 나이·BMI·허리둘레·흡연·음주·운동·가족력만 모델에 입력
              → 저장된 모델로 추론 → 위험도 + SHAP 설명 출력
              → 혈압 실측값은 대시보드에 별도 표시 (모델 입력에는 미포함)
```

사용자 입력 항목 자체는 실제 국가건강검진 결과지 항목을 그대로 따르되, 그중 일부(혈압 실측값)는
라벨 누수 방지를 위해 모델 피처에서 제외하고 대시보드 표시 전용으로만 사용함.

### 5. 정리

데이터는 **Framingham(라벨 누수 없는 구조)** + 모델은 **로지스틱회귀 vs XGBoost 비교** + 설명은 **SHAP** —
이 구성은 당뇨병 검토 때 논의했던 라벨 누수 방지 원칙을 고혈압에 그대로 적용한 버전임.
