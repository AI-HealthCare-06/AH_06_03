**어떤 틀로 시작했나**

- **MVP 통합 데모 (9/28):** 흩어져 있던 데모 3개를 한 파일로 합쳐 직접 눌러 볼 수 있게 했어요. 이때 요구사항 정의서에서는 모델 A 단독으로 정리했어요(팀 결정, 이후 9/29 멘토링 뒤 모델 B 복원).
- **프론트 구현 (9/30):** 화면 15장을 **프레임워크 없는 정적 HTML/JS**로 만들었어요(가입·로그인·동의·건강정보·설문·리뷰·예측 결과·대시보드·챌린지·내 기록·마이페이지). 데이터는 브라우저(localStorage)에 두고, 서버가 준비되면 `assets/api.js` 한 곳에서 가짜 데이터와 실제 서버를 바꿔 끼우는 구조였어요.
- **색과 틀:** 색 이름은 분홍 계열(`--sage-*`)이었고, 화면은 가운데 프레임에 왼쪽 사이드 메뉴가 붙는 **컴퓨터 화면 구조**였어요.

**이 시기에 추가한 것:** 예측을 실제 서버에 연결, 캘린더 상세 화면(일기·사진·일정·할 일), 서버 주소를 고정 도메인(HTTPS)으로 변경.

## 2. 서버 연결과 규칙 개편 (10/1~10/8)

**10/1~10/6: 화면을 서버에 하나씩 연결**

**10/8: 규칙이 크게 바뀐 날 (하루 43건)**
모델 입력 가이드(혜성)가 확정되면서 입력·설문·챌린지가 한꺼번에 바뀌었어요.
- **12주 = 4주 × 3번** 구조로 챌린지를 개편했어요(가이드 §2~§6). 선택·진행 규칙, 혈압은 시작과 4주 재입력 때만 입력.
- 건강정보에 일반담배 빈도·전자담배를 추가했고, 설문 v2(나트륨 11문항, 신체 활동, 외식, 아침 식사)로 바꿨어요.
- **동의 철회, 회원 탈퇴, 데이터 내려받기**를 서버 API와 화면에 연결했어요. 동의 정책 v2 문구를 만들고 가입 화면에서 약관 내용을 볼 수 있게 했어요.
- 대상 확인 답을 서버에 저장하고 복원(이슬이 서버 코드도 직접 작성: `eligibility_assessments` 형태).
- 가입·로그인 흐름을 정리하고 약관을 3개로 나눴어요. 개인정보 처리방침 페이지를 추가했어요.
- 팀이 한 **테스트 점검(#1~#11)** 을 반영했어요: HDL·혈압 측정 방법 문항 삭제, 숫자 칸 화살표 숨김, 결과 화면 문구와 요인 표시 정리, 개발용 상태 전환 버튼 삭제.

## 5. 다듬기와 모델 반영 (10/20)

- **건강정보 입력을 8단계 + 확인 화면**으로 바꿨어요(한 번에 한 묶음씩 묻기). 처음 한 장짜리 긴 폼이 막힌다는 판단이었어요.
- **내 12주 계획 화면:** 분석 후 계획을 먼저 보여 주고, 홈에 "12주 중 N주차"를 표시.
- **파이 접시와 김** 같은 선 요소, 이모지를 선 아이콘으로, 미션 체크 때 움직임.
- **접근성:** 글자 대비 4.5:1 미만 해소, 작은 터치 영역을 44px 이상으로(10/21까지).
- **첫 화면 소개:** 영상(10/12)을 실제 화면 캡처 슬라이드로 바꾸고 아이폰 틀 안에 넣었어요(멘토님이 "동영상 대신 캡처 화면"으로 소개하라고 한 흐름).
- **모델 A v0.2.0 반영(4차 멘토링 10/20):** 확률(%) 표시, 같은 성별·연령대 상위 %, 확률 근거를 문구 옆 열고 닫는 토글로. 상담 권고 배너 조건을 혜성님 기준(140/90·160/100 이상 또는 모델 A 높음)으로 맞춤.
- 처리방침: 디스크 암호화 완료, 서버 접속·배포 인원 구분, 백업 보관, 관리자 권한 이력 3년, "철회하면 서비스를 이용할 수 없다" 명시.

## 6. 체험 자동 채움 (10/21)

**문제:** 지인 체험 기간이 4일(10/22~25)이라 4주·12주 결과 화면을 직접 볼 수 없었어요.
**해결:** 3일만 기록하면 나머지 4주를 가상 기록으로 채워서 4주 재입력, 내 변화, 4주 비교 화면을 볼 수 있게 했어요(이슬이 서버와 화면을 같이 구현).
- 패턴 세 가지(꾸준함 / 중간에 흔들림 / 후반에 놓침)를 사람마다 배정하고, **가상 기록이 섞였다는 것을 안내창과 결과 화면에 솔직하게 표시**했어요.
- 체험 종료 안내, 결과 보기 버튼, 3일째 이후 기록 막기, 체험 종료 상태(10/22).
- 같은 날 챌린지 중단 이유 선택, 처음 건강정보 수정 잠금 안내, 12주 결과 화면(처음↔12주 비교, 서버 `weeks_done` 반영).

## 이슬이 만든 서버 API (브랜치 `yiseul_2`, 모두 main에 머지됨)

화면(프론트)과 별개로 서버 API도 이슬이 직접 만들었어요. 기능별로 정리했고, "공동"은 다른 팀원이 만든 파일에 이슬이 더한 부분이에요.
주소 앞에는 `/v1`이 붙어요.

### 이슬이 처음 만든 기능

|---|---|---|

### 공동 (다른 팀원의 파일에 더한 것)

| 파일 | 이슬이 더한 것 |
|---|---|
| 관리자(`admin`, 효민이 시작) | 가입자 목록·상세, 테스트 계정 일괄 삭제(10/13), 회원 이용 정지(기간·무기한)·해제·삭제와 정지 중 로그인 차단(10/15), 문의 관련 관리자 API |
| 파티(`party`, 혜림이 시작) | 파티 피드(파티원에게만 보이는 글, 전체 목록 제외, 파티 삭제 시 함께 삭제), 파티 글에 연속 인증 카드 붙이기·검색(10/15) |
| 로그인·가입(`auth`, 혜림이 시작) | `PATCH /users/me` 생년월일 변경(만 19세 이상), 가입 때 동의 값 검사·기록(10/14), 서비스 접속(로그인) 기록 3개월 보관과 관리자 권한 부여·회수 기록(10/14) |
| 챌린지(`challenge`, 혜성이 시작) | 체험 자동 채움(3일 기록 → 나머지 4주, 패턴 3가지, 결과 보기, 체험 종료 상태, 4주 비교의 `demo_fill`), 4주 재평가 나이 기준, 전자담배 사용자를 금연 미션 대상에 포함 (10/21~10/22) |
| 건강정보·설문·홈·배지 | 터무니없는 입력 막기(키·몸무게·허리·혈압 범위, 수축기>이완기, BMI 10~60), 배지의 받기까지 진행 값(progress/target) |
| 알림(`notify_service`, 혜림이 시작) | 내 글 좋아요·인기도 받음 알림 연결(10/23) |
| 캐릭터 | 눈 색 8가지(무료 5, 10파이 3) 항목(10/23) |

### 이 API들을 만들면서 지킨 것
- 건강정보 동의를 철회하면 이 기능들도 막혀요(커뮤니티·파이·공통 챌린지 등은 동의 검사 대상). 문의·동의·탈퇴는 철회 뒤에도 열려 있어요.
- 관리자 API는 관리자만 쓸 수 있고, 열람·변경은 관리자 행위 기록에 남아요(2년 보관).
- 새 표가 필요한 기능은 마이그레이션으로 추가했어요(눈 색, 댓글 좋아요 등 3개는 서버 PR 머지 후 `alembic upgrade head`가 필요했어요).
- 각 기능마다 시험을 같이 추가했어요(`test_community`, `test_pie_ledger`, `test_party_feed`, `test_demo_autofill`, `test_notifications` 등).
