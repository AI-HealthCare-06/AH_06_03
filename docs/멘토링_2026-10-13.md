# 멘토링 정리 (2026-10-13 화)

> 전사본을 기준으로 정리했어요. 고유명사 오인식이 있어서, 의미가 불확실한 내용은 맨 아래 "확인 필요"에 따로 모았어요.

## 한 줄 요약

- 개인정보는 **법적 기준을 준수하는 방향**으로 가고, 관리자 접속 기록은 **1년 보관**으로 맞춰요.
- 앱(Capacitor)보다 **모바일 웹(PWA)** 으로 가요.
- 지인 테스트는 **20명 이상**, NPS 설문, 포커스 그룹 3명으로 해요.
- 챌린지 UI/UX와 동기 부여가 가장 큰 개선 과제예요.

## 1. 우리가 고민하던 질문에 대한 답

| 질문 | 멘토님 답 |
|---|---|
| 법을 따라야 하나, 자체 기준으로 명시만 하면 되나 | 법적 기준을 준수하는 쪽을 권장해요. 카카오 파스타 수준으로 하길 권했고, 구현 난이도는 높지 않다고 했어요. |
| 접속기록 보관 기간 | 관리자 접속 기록은 **1년 보관**해요. 개인정보 취급자·관리자의 시스템 접속 기록과, 관리자로 등록한 이력(권한 부여 로그)을 남겨야 해요. 배포·백업 이력은 안 남겨도 돼요. |
| 지인 체험 데이터는 얼마나 보관하나 | 알파 테스트라면 **즉시 파기**하거나 **"10/20 이후 일주일 안에 파기"처럼 기한을 고지**하면 돼요. 정식 서비스는 2년 보관을 명확히 고지해야 해요. |
| 탈퇴하면 | 사용자 정보는 **즉시 파기**해요. 재가입 제한은 필요 없어요. |
| 건강정보 동의를 거부하면 | **서비스 이용이 제한된다는 것을 명확히 안내**해야 해요. |

> 지금 처리방침의 "관리자 열람·변경 기록은 체험 종료 후 일주일 안에 삭제"는 멘토님 기준(1년)과 달라요. 1년으로 바꾸는 쪽으로 가야 해요.

## 2. 보안·개인정보 조치

- **디스크 암호화**: AWS에서 RDS는 기본 암호화가 되지만, EC2의 디스크(EBS)는 직접 설정해야 해요. 멘토님은 암호화를 권장했어요.
- **컬럼 단위 암호화**: 이메일과 건강정보(혈압 등)가 대상이에요. 비밀번호는 해시로 충분해요. 모든 컬럼을 하는 건 아니고, 개인정보와 민감정보를 분류해서 정해요.
- **통신 구간**: HTTPS로 따로 관리해요(이미 적용).
- **서버 접속**: PEM 키 대신 **AWS 세션 매니저**를 쓰고 PEM은 폐기해요. PEM으로 접속하면 기록이 거의 안 남아요. 클라우드 트레일로 접속 기록을 볼 수 있어요(비용 발생 가능).
- **토큰**
  - access 토큰은 유효기간을 짧게 해요.
  - refresh 토큰은 **로테이션**(재발급 시 기존 토큰 삭제)으로 해요.
  - **탈퇴 계정의 토큰은 무효화하거나 블랙리스트에 등록**해요. 탈퇴 직후에도 로그인이 되는 문제를 지적했어요.
- **위탁·국외 이전**: 이용약관과 처리방침에 **AWS 서버 위탁과 서울 리전 저장을 명시**하고, 국외 이전을 하지 않는다고 적어요(이미 명시).
- **백업**: 7일 주기면 충분해요. 서버 밖 자동 백업은 이번 범위 밖이에요. RDS는 자체 백업 기능이 있어요.
- **동의 기록**: 회원가입 시 동의 내용을 모두 기록해요(이미 저장 중).

## 3. 표현·법적 이슈

- "진단" 대신 **예측·분석**, "위험도" 대신 **위험 신호**로 바꾼 건 좋다고 했어요.
- 의료기기 해당 여부는 변호사 영역이라 확답은 못 해요. 다만 **건강 나이나 유사 집단 비교** 방식이 의료기기성 면책에 유리하다고 했어요. (우리 화면의 "혈관 나이"와 "나와 비슷한 사람들과 비교"가 해당돼요.)
- **12주 결과만으로 "건강이 좋아졌다"고 결론 내리면 의료기기 문제**가 될 수 있어요. 지인 테스트와 정식 운영은 구분해서 다뤄요.
- 지인에게 **기프티콘을 주려면 개인정보 수집 동의 체크박스가 필수**예요. 목적은 "**생활 습관 관리용 위험 신호 안내**"로 적어요.
- 구글폼에서 이름이나 전화번호를 받는 건 주의해요.

## 4. 지인 테스트·설문

- **20명 이상** 권장해요(통계적 의미).
- 설문 핵심
  - **NPS**(추천 의향 1~10점)
  - 계속 쓰고 싶은 이유
  - 개선 아이디어
  - 결과가 "양호"일 때 "건강에 문제가 없다"고 이해하는지
- **포커스 그룹 인터뷰 3명 정도**로, 의도대로 이해하는지 확인해요.
- **12주(4주 × 3사이클) 가상 데이터를 많이 만들어서**, 착실히 한 경우와 안 한 경우의 결과 차이를 직접 확인해요.
- 일정: 이번 주말~다음 주 초 배포, 다음 주부터 응답 수집.

## 5. UI/UX·제품 방향

- **모바일 앱 대신 모바일 웹(PWA)** 으로 가요. 앱 개발은 이번 프로젝트 범위에 과해요. 알림은 PWA 바로가기 방식으로 해요.
- 현재 화면이 **좁고 모바일 최적화가 부족**해서 일반 웹 서비스 수준에 못 미쳐요.
- **챌린지 UI/UX가 불명확**해요. 어떻게 쓰는지 헷갈리고, 재미나 보상 체계가 안 보여서 동기가 부족해요.
- 참여가 저조하거나 변화가 없는 사람도 계속하게 **게임화, 칭찬, 수치 제공** 같은 장치가 필요해요(4주 후 이어지는 8주를 위해서).
- 1~2주차에 비해 3주차 진척이 부족해요. 한 사이클을 완성한 지금, **매끄럽고 미려한 UI로 다듬는 게 과제**예요.
- 에러는 발견 즉시 고치고, 사용자가 척척 조작하는 느낌을 주는 게 중요해요.
- 무중단 배포는 서버 사양 문제로 **2주 뒤 재논의**해요.

## 6. 포트폴리오·마무리

- 이력서와 포트폴리오에 **문제 정의 → 원인 분석 → 수정 → 재확인** 과정을 적어요.
- 개인정보 보호법 준수와 보안 조치 경험을 발표 자료와 포트폴리오에 반영해요.
- 프로젝트가 끝나면 서버를 종료하니, **데모 영상과 캡처로 기록**을 남겨요.
- 서버 지식은 각자 주력 분야를 깊게, 다른 영역은 적절한 수준으로 이해해요(T자형·파이형).
- 다음 만남: **다음 주 화요일 7시 30분**
