## 1. 입력 명세

### 1.1 필드 목록
나이·성별은 프로필(REQ-HEALTH-001), 나머지는 W04 건강정보 입력·W04-2 설문.

| 필드 | 형식 | 단위·범위 | 필수 | 모델 A | 모델 B | 화면 |
|---|---|---|---|---|---|---|
| `age` | 정수 | 세, 19 이상 | 필수 | ✅ | ✅ | 프로필 |
| `sex` | `"M"` / `"F"` | | 필수 | ✅ | ✅ | 프로필 |
| `height_cm` | 숫자 | cm (예 120–220) | 필수 | ✅ BMI | ✅ BMI | W04 |
| `weight_kg` | 숫자 | kg (예 30–200) | 필수 | ✅ BMI | ✅ BMI | W04 |
| `waist_cm` | 숫자 | cm (예 50–150) | 필수 ⚠️ **신규** | — | ✅ | W04 (**현재 칸 없음**) |
| `sbp` | 숫자 | mmHg | 필수 | ✅ | ❌ (판정·대시보드용) | W04 |
| `dbp` | 숫자 | mmHg | 필수 | ❌ | ❌ (판정·대시보드용) | W04 |

| `smoking` | 선택지 §1.2 | | 필수 | ✅ | ✅ | W04 |
| `diabetes` | true / false | | 필수 | ✅ | — | W04 |
| `htn_status` | `"none"` / `"diagnosed_untreated"` / `"treated"` | | 필수 | ✅ | 적용 조건 | W04 |

| (또는) `aerobic` | 0 / 1 | 위 두 값 대신 직접 | | — | ✅ | |

- ⚠️ `waist_cm`, `drink_amount`는 PRD v1.9(`docs/요구사항_정의서_파이온.xlsx`) REQ-HEALTH-002에 추가함. 와이어프레임 v4·v5, 데모 W04에는 아직 칸이 없음
- 선택 항목·설문이 비면 예측은 수행하고 `missing_features`로 알려줌 (§3)
- BMI는 서버가 `weight_kg / (height_cm/100)²`로 계산 (predict 함수 안에서 계산함)

### 1.2 선택지 → 값 변환표 (학습 데이터 코드와 1:1)
**화면 선택지를 아래 값으로 보내면 predict가 학습 때와 같은 방식으로 변환함.** 선택지 문구는 국민건강영양조사 조사표 문구 그대로 쓰는 것을 권장 (그래야 학습 데이터와 뜻이 같음).

**흡연 `smoking`** (조사 원본 `BS3_1`)
| 화면 선택지 | 값 | 모델 A | 모델 B |
|---|---|---|---|
| 현재 피움 (매일 또는 가끔) | `"current"` | 흡연 1 | 현재 흡연 1 |
| 과거엔 피웠으나 지금은 안 피움 | `"former"` | 흡연 0 | 과거 흡연 1 |
| 피운 적 없음 | `"never"` | 흡연 0 | 둘 다 0 |

**음주 빈도 `drink_freq`** (원본 `BD1_11`, 최근 1년)
| 화면 선택지 | 값 |
|---|---|
| 평생 술을 마셔 본 적 없음 | `"never_lifetime"` |
| 최근 1년간 전혀 마시지 않음 | `"none_past_year"` |
| 한 달에 1번 미만 | `"lt_monthly"` |
| 한 달에 1번 정도 | `"monthly"` |
| 한 달에 2–4번 | `"2_4_per_month"` |
| 일주일에 2–3번 | `"2_3_per_week"` |
| 일주일에 4번 이상 | `"4plus_per_week"` |

**한 번 음주량 `drink_amount`** (원본 `BD2_1`, 소주·양주 구분 없이 각 술잔 기준, 캔맥주 1개 = 맥주 1.5잔, 소주 1병 = 7잔)
| 화면 선택지 | 값 |
|---|---|
| 1–2잔 | `"1_2"` |
| 3–4잔 | `"3_4"` |
| 5–6잔 | `"5_6"` |
| 7–9잔 | `"7_9"` |
| 10잔 이상 | `"10plus"` |
- `drink_freq`가 `never_lifetime`·`none_past_year`면 **묻지 않음** (보내지 않거나 null, predict가 0으로 처리)

**아침 식사 `breakfast`** (원본 `L_BR_FQ`, 최근 1년 동안 1주에 몇 회)
| 화면 선택지 | 값 |
|---|---|
| 주 5–7회 | `"5_7"` |
| 주 3–4회 | `"3_4"` |
| 주 1–2회 | `"1_2"` |
| 거의 안 함 (주 0회) | `"0"` |

**외식·배달 `eatout`** (원본 `L_OUT_FQ`, 최근 1년 평균. 조사표 정의에 배달·포장 포함)
| 화면 선택지 | 값 |
|---|---|
| 하루 2회 이상 | `"2plus_per_day"` |
| 하루 1회 | `"1_per_day"` |
| 주 5–6회 | `"5_6_per_week"` |
| 주 3–4회 | `"3_4_per_week"` |
| 주 1–2회 | `"1_2_per_week"` |
| 월 1–3회 | `"1_3_per_month"` |
| 거의 안 함 (월 1회 미만) | `"lt_monthly"` |

**유산소 신체활동** (원본 `pa_aerobic`) — 설문의 운동 종목·시간으로 주당 중강도·고강도 분을 계산해 보냄
- 실천(1) = 중강도 주 150분 이상 **또는** 고강도 주 75분 이상 **또는** 중강도 + 고강도×2 ≥ 150분
- 🟡 지침서 정의를 분 단위로 단순화한 것 (걷기 포함 여부 등 세부 규칙은 두 번째 사이클에서 맞출 예정)

**고혈압 진단·치료 상태 `htn_status`** (PRD v1.8 선택지 그대로)
| 화면 선택지 | 값 | 모델 A | 모델 B |
|---|---|---|---|
| 진단받은 적 없음 | `"none"` | 고혈압 0, 약 0 | 예측함 |
| 진단받았지만 약은 안 먹음 | `"diagnosed_untreated"` | 고혈압 1, 약 0 | **예측 안 함** |
| 진단받았고 약을 먹는 중 | `"treated"` | 고혈압 1, 약 1 | **예측 안 함** |

### 1.3 현재 데모 선택지와 다른 점 (프론트 수정 필요)
| 항목 | 데모 현재 | 필요한 것 |
|---|---|---|
| 흡연 | 비흡연 / 흡연 (2개) | 3개 (현재 / 과거 / 피운 적 없음) — 모델 B가 과거 흡연을 따로 씀 |
| 음주 빈도 | 5개 (안 마심 ~ 주 4회 이상) | 7개 (§1.2). "안 마심"이 평생인지 최근 1년인지 구분 필요, "월 1회 이하"는 2개로 나뉨 |
| 한 번 음주량 | 없음 | 추가 (§1.2) |
| 허리둘레 | 없음 | 추가 |
| 부모 가족력 | 없음 / 있음 | + "모름" |
| 외식·배달 | 배달 주 ○회 + 외식 주 ○회 (2문항) | 1문항 7단계 권장. 2문항을 유지하면 합산해서 변환: 주 합계 14회 이상 → `2plus_per_day`, 7–13 → `1_per_day`, 5–6 → `5_6_per_week`, 3–4 → `3_4_per_week`, 1–2 → `1_2_per_week`, 0 → `lt_monthly` 🟡 |
| 아침 | 주 0 / 1–2 / 3–4 / 5–6 / 매일 | 5–6·매일 → `"5_7"`, 나머지는 그대로 |
| 데모 모델 A `FEATS` | `hdl` 포함, `bmi`·`prevalentHyp` 없음 | `demo_snippet.js`의 `MODEL_A_FEATS`로 교체 |
| 데모 설문 안내 문구 | "이 설문의 답은 예측 모델 입력이 아닙니다" | 모델 B 입력으로도 씀 (PRD v1.9 REQ-HEALTH-005) |

## 2. 계산 방법

### 2.1 백엔드 (Python)
```python
from paeon_models import predict_model_a, predict_model_b

user = {"age": 45, "sex": "M", "height_cm": 172, "weight_kg": 78, "waist_cm": 88,
        "sbp": 145, "dbp": 92, "total_chol": 212, "smoking": "current", "diabetes": False,
        "htn_status": "none", "parent_htn": "yes", "drink_freq": "2_3_per_week", "drink_amount": "5_6",
        "breakfast": "1_2", "eatout": "1_per_day", "moderate_min_per_week": 60, "vigorous_min_per_week": 0}
a = predict_model_a(user)   # dict (§3)
b = predict_model_b(user)
```
- 두 함수는 서로 독립. 한쪽이 `skipped`여도 다른 쪽은 그대로 씀 (NFR-ARCH-003)
- 모델 파일 경로는 `paeon_models.py`의 `SPEC_A`, `SPEC_B`. 버전을 바꿀 때는 JSON 파일만 교체

### 2.2 데모 (JS)
확률은 데모의 기존 계산식(`risk`)과 같은 형태: `p = σ(INTERCEPT + Σ coef·(x − mean))`
- **기여도는 데모와 다름**: `coef·(x − baseline)`. `baseline`은 있다/없다 요인(성별·흡연·당뇨·혈압약·고혈압 진단·가족력·유산소)은 0(없음), 숫자·단계 요인은 평균. 기여도가 0이면 "해당 없음"이라 표시하지 않음 (비흡연자에게 "흡연"이 요인으로 뜨지 않게)
- `demo_snippet.js`의 `MODEL_A_FEATS`·`MODEL_A_INTERCEPT`를 데모 `FEATS`·`INTERCEPT` 자리에 넣음
- 피처 키 이름이 데모와 다름 → `X()` 함수가 아래 키로 값을 만들어야 함
  - 모델 A: `age, male, sysBP, totChol, currentSmoker, diabetes, BPMeds, prevalentHyp, BMI`
  - 모델 B: `age, male, bmi, waist, parent_htn, smoke_current, smoke_former, drink_freq, drink_amount, aerobic, breakfast_skip, eatout` (값 변환은 `paeon_models.py`의 `features_b`와 똑같이)
- 데모의 혈관 나이 식이 `AGE_COEF`를 쓰면 모델 A 나이 계수 **0.066053**으로 맞출 것 (혈관 나이 표현 자체는 두 번째 사이클 재검토)

## 3. 출력 명세

```json
{
  "model_code": "MODEL_A",
  "model_version": "0.1.0",
  "status": "completed",
  "skip_reason": null,
  "probability": 0.150995,
  "risk_level": "borderline",
  "percentile": null,
  "factors": [ { "code": "male", "label": "성별(남)", "value": 1, "value_label": "남", "contribution": 0.551428,
                 "direction": "risk_increase", "modifiable": false,
                 "direction_matches_expectation": true, "display_rank": 1 },
               { "code": "currentSmoker", "label": "흡연", "value": 1, "value_label": "있음", "contribution": 0.386011,
                 "direction": "risk_increase", "modifiable": true,
                 "direction_matches_expectation": true, "display_rank": 2 }, "..." ],
  "top_risk_factor": { ... },
  "top_modifiable_factor": { ... },
  "missing_features": []
}
```

| 필드 | 뜻 | 모델 A | 모델 B |
|---|---|---|---|
| `status` | `completed` / `skipped` | | |
| `skip_reason` | `age_out_of_range` / `htn_diagnosed` (skipped일 때만) | 32–70세 밖 | 19세 미만, 고혈압 진단·치료 중 |
| `probability` | 0–1 확률 | 10년 내 관상동맥질환 (**보정 전, 그대로 % 표시 금지**) | 경계군과 닮은 정도 |
| `risk_level` | `normal` / `borderline` / `high` | 정상 <0.10 · 경계 0.10–0.20 · 위험 >0.20 (데모 기준) | **null** (판정 안 함) |
| `percentile` | 같은 성별·연령대 상위 % | null (보정 사이클에서) | null |
| `factors` | 기여도가 0이 아닌 요인, 기여도 큰 순 (0 = 해당 없음은 뺌) | | |
| `factors[].value_label` | 값의 뜻 (예: "있음", "주 2–3회"). 숫자 요인은 null → `value` 그대로 표시 | | |
| `factors[].contribution` | 로그 오즈 기여도 (+ = 위험↑). 기준점 = 있다/없다 요인은 "없음", 숫자·단계 요인은 학습 데이터 평균 | | |
| `factors[].modifiable` | 챌린지로 바꿀 수 있는 요인인지 | | |
| `factors[].direction_matches_expectation` | 학습 방향이 상식과 같은지. **false여도 걸러내지 않음** (데이터_특성 §2.4) | 전부 true | 흡연 2개·외식·유산소 false |
| `top_risk_factor` | 기여도 + 중 1위 (REQ-PRED-003 강조) | | |
| `top_modifiable_factor` | 기여도 + 이면서 개선 가능한 것 중 1위 → 챌린지 연결 | | |
| `missing_features` | 비어서 중앙값으로 채운 피처 → "정확도 한계" 표시 | | |

- DB 매핑: `probability` → `predictions.score`, `risk_level` → `predictions.risk_level`, `factors` → `prediction_factors` (code·direction·contribution→importance·modifiable·display_rank), `model_version` → `model_versions` (ERD v5)
- ERD v5의 `factor_direction`은 `risk_increase` / `protective` → 출력과 같음
- 모델 B 결과 저장에는 ERD에서 제거된 MODEL_B 행·결과 카드 유형(`current_lifestyle` 등)을 되살려야 함 (PRD v1.9 REQ-PRED-006 카드 3개)

- 반복 일관성: 같은 입력 10회 → 편차 0 (확인함, NFR-ML-005)

## 6. 혈압 판정 규칙 (모델 아님 · 백엔드 규칙)

모델 B는 판정을 하지 않음(`risk_level = null`). 현재 혈압 상태는 **입력 혈압으로 규칙 판정**함. 기준은 모델 B 라벨과 같은 국민건강영양조사 `HE_HP` 정의 (이용지침서 원문 대조).

| 단계 | 기준 (수축기 SBP / 이완기 DBP, mmHg) | 모델 B 학습 라벨 |
|---|---|---|
| 정상 | SBP < 120 **그리고** DBP < 80 | 0 |
| 주의혈압 | SBP 120–129 **그리고** DBP < 80 | 1 (경계군) |
| 고혈압전단계 | SBP 130–139 **또는** DBP 80–89 | 1 (경계군) |
| 고혈압 | SBP ≥ 140 **또는** DBP ≥ 90 (또는 혈압약 복용) | 학습 제외 |

```python
def bp_stage(sbp, dbp):
    if sbp >= 140 or dbp >= 90:  return "hypertension"      # 위에서부터 차례로 확인
    if sbp >= 130 or dbp >= 80:  return "prehypertension"   # (수축기·이완기 중 높은 쪽 단계가 적용됨)
    if sbp >= 120:               return "elevated"
    return "normal"
```

**단계별 서비스 흐름** 🟡 (모델링 제안, 모델 개발 계획 §1-1 · 9/28 회의 공유)
| 혈압 단계 | 안내 | 모델 B가 더해주는 것 |
|---|---|---|
| 정상 | 정상 | 경계군과 닮은 정도 (`probability`) |
| 주의혈압 · 고혈압전단계 (= 경계군) | 경계군 | 위험을 높인 요인 → `top_modifiable_factor` → 챌린지 (§7) |
| 고혈압 범위 + `htn_status = "none"` (미진단) | 의료기관 검사·상담 권고 (REQ-PRED-005) | 모델 B는 예측하되 판정은 규칙이 우선 |
| `htn_status` 진단·치료 중 | 관리 중 사용자 | 모델 B 예측 안 함 (`skipped`) |

- 대시보드 혈압 기준선 140mmHg(REQ-DASH-010)과 같은 기준
- 판정 문구에 "진단" 표현 금지 (REQ-PRED-005, NFR-SAFE)

## 7. 요인 → 챌린지 카테고리 연결표

PRD REQ-CHAL-008("나트륨도 이미 낮으면 **기여도가 가장 큰 개선 가능 요인**으로 대체")과 REQ-PRED-003("개선 가능 요인은 챌린지로 연결")에서 쓰는 표. 출력의 `top_modifiable_factor.code`로 찾음. 카테고리 이름은 PRD `미션 카탈로그` 시트 기준.

| 모델 | 요인 `code` | 챌린지 카테고리 (카탈로그 상태) | 비고 |
|---|---|---|---|
| B | `waist`, `bmi` | 체중 관리 (**Backlog**) | 모델 B에서 가장 강한 개선 가능 요인. 카테고리가 MVP가 아니라 연결할 곳이 없음 → **MVP 격상 여부 팀 결정 필요** |
| A | `BMI` | 체중 관리 (Backlog) | 위와 같음 |
| B | `drink_freq`, `drink_amount` | 흡연·음주 → 절주 (MVP) | 방향 정상 ✅ |
| A | `currentSmoker` | 흡연·음주 → 금연 (MVP) | 모델 A에서 방향 정상 ✅ |
| B | `smoke_current` | 흡연·음주 → 금연 | ⚠️ 모델 B에서는 반대 방향(`direction_matches_expectation=false`) → 기여도가 +로 나오지 않아 `top_modifiable_factor`로 뽑히지 않음. 금연 근거는 모델 A 사용 |
| B | `eatout` | 외식·배달 (MVP) | ⚠️ 반대 방향 → 외식이 **적은** 사람에게 + 기여도 → 그대로 연결하면 외식이 적은 사람에게 "배달 줄이기"가 추천됨. **연결 여부 팀 결정 필요** |
| B | `aerobic` | 신체 활동 (MVP) | ⚠️ 반대 방향 → 운동하는 사람에게 + 기여도. **연결 여부 팀 결정 필요** |
| B | `breakfast_skip` | 아침 식사 (**검토**) | 영향 거의 없음(오즈비 1.00) |
| A | `sysBP` | 🟡 나트륨 · 신체 활동 · 체중 관리 중 선택 | 혈압을 낮추는 생활습관은 문헌 근거. 모델은 "혈압이 위험을 높였다"까지만 말함 |
| A | `totChol` | 해당 카테고리 없음 | 지침 안내만 |
| A·B | `age`, `male`, `parent_htn`, `diabetes`, `BPMeds`, `prevalentHyp`, `smoke_former` | 없음 (`modifiable=false`) | 설명에만 표시, 챌린지 연결 안 함 |

- 나트륨 챌린지는 모델 입력이 아님 → 설문 5문항 점수(REQ-PRED-008)로 판단
